# 검증 가이드

"만들어진 게 제대로 동작하는가"를 직접 확인하는 절차. 위에서부터 순서대로 하면 된다.

## 0. 실행

```bash
npm install
npm run test
npm run dev
```

`npm run dev` 는 `--host` 로 뜨므로 터미널에 `Network: http://192.168.x.x:5173/` 같은 줄이
같이 나온다. **태블릿을 같은 Wi-Fi 에 두고 그 주소로 접속**하면 실기기 테스트가 된다.

| URL | 용도 |
|---|---|
| `http://localhost:5173/` | 실제 배포와 동일. 터치만 유효, 마우스는 무시된다 |
| `http://localhost:5173/?debug=stats` | 하단에 입력 필터 통계 패널 표시 (터치만 유효) |
| `http://localhost:5173/?debug=mouse` | 위 + **마우스도 유효 입력으로 허용** (데스크톱 확인용) |

`?debug=...` 로 들어가면 콘솔에서 `__touchFlip.state`, `__touchFlip.governor.stats`,
`__touchFlip.config` 로 내부 상태를 직접 볼 수 있다.

> 배포 기본 경로(`?debug` 없음)에서는 마우스가 무시되는 게 **정상**이다.
> 데스크톱에서 마우스로 눌렀는데 카드가 안 뒤집힌다면 버그가 아니라 사양이다.

## 1. 통계 패널 읽는 법

`?debug=stats` 화면 맨 아래 줄:

```
입력 152 · 방출 61 · 반영 58 | 타입 40 · 크기 3 · 중립/바깥 12 · 포인터초과 5 · 쿨다운 31 · 락아웃 2 · 상태거부 3
```

- **입력** = 받은 pointerdown 전체
- **방출** = 모든 공정성 필터를 통과해 GameState 로 넘어간 수
- **반영** = 실제로 카드가 뒤집힌 수
- 나머지는 각 필터가 거부한 횟수다. 어떤 규칙이 실제로 동작했는지 이 숫자로 확인한다.

## 3. 태블릿 실기기 확인 (여기가 진짜다)

마우스로는 재현되지 않는 것들이라 반드시 실기기에서 해야 한다.

| # | 조작 | 기대 결과 |
|---|---|---|
| 1 | 보드를 위아래로 쓸어보기 | 페이지가 스크롤되지 않는다 |
| 2 | 카드를 빠르게 두 번 탭 | 화면이 확대되지 않는다 |
| 3 | 카드를 길게 누르기 | 복사/공유 메뉴가 뜨지 않는다 |
| 4 | 손가락을 카드에 대고 **드래그** | 지나간 카드가 뒤집히지 않는다 (pointerdown 만 유효) |
| 5 | **손바닥/손날로 보드를 덮기** | 카드가 뒤집히지 않는다. `크기` 카운터 증가 |
| 6 | 한 사람이 손가락 **3개 이상**으로 동시 연타 | 동시에 2개까지만 먹는다. `포인터초과` 증가 |
| 7 | 스타일러스 펜으로 터치 | 무시된다 (`타입` 증가) |
| 8 | 두 사람이 **같은 카드를 동시에** 노리기 | 먼저 닿은 쪽이 가져가고, 0.2초간 상대는 못 뺏는다 |
| 9 | 홈화면에 추가 후 실행 | 주소창 없이 전체화면으로 뜬다 |
| 10 | 기기를 90도 돌리기 | 보드가 화면 중앙을 유지하고 판정이 어긋나지 않는다 |

### 실제로 3판을 해 본다

v1 완료 기준은 "두 사람이 3판을 끝까지 하고 판정에 불만이 나오지 않는다" 이다.
불만이 나오면 **코드가 아니라 `src/config.ts` 의 숫자를 먼저 조정**한다.

| 증상 | 손볼 값 |
|---|---|
| "분명히 눌렀는데 안 먹었다" | `PLAYER_COOLDOWN_MS` ↓, `CARD_LOCKOUT_MS` ↓ |
| "손바닥으로 밀어도 먹힌다" | `MAX_TOUCH_SIZE_PX` ↓ |
| "손가락 많은 쪽이 무조건 이긴다" | `MAX_POINTERS_PER_PLAYER` ↓ (1까지 낮출 수 있다) |
| "옆 카드가 잘못 눌린다" | `NEUTRAL_BAND_RATIO` ↑ |
| "카드가 너무 작다/크다" | `CARD_PHYSICAL_SIZE_MM` |
| 시간 선택지를 바꾸고 싶다 | `ROUND_DURATION_OPTIONS_MS` |
| NPC 가 너무 세다/약하다 | `npc.tiers[n].tapsPerSec`, `accuracy` |

값을 바꾸면 `npm run test` 를 다시 돌린다. 상수를 참조하는 테스트라 대부분 그대로 통과하지만,
규칙 자체를 바꿨다면 실패로 알려준다.

## 4. 자동 검증

```bash
npm run test
```

86개 테스트가 통과해야 한다 (서버 JUnit 40개는 별도, `cd server && ./gradlew test`). 다루는 범위:

- **GameState (31)** — 준비/카운트다운/취소, 라운드 길이, 소유권 전환과 뺏기,
  자기 카드 재탭 거부, 라운드 종료 시각 이후의 탭 거부, 부정 출발 페널티,
  라운드 승패, 3판 2선승, 무승부 라운드 재경기, 보드 회전, 매치 재시작
- **InputGovernor (30)** — 포인터 종류(터치만), 접촉 크기, 중립 띠,
  동시 포인터 수, 유실된 포인터 회복, 플레이어별 쿨다운, 카드 락아웃,
  `event.timeStamp` 사용, 통계 집계, NPC 경로(`submitTap`)의 쿨다운·락아웃
- **NpcPlayer (14)** — 자동 준비, 카운트다운 중 무행동, 예약 시각 사용,
  속도 = tapsPerSec, 쿨다운 상한, 백로그 폐기, 카드 선택 규칙, GameState 통합
- **RemoteState (11)** — 서버 배열 → 레코드 변환, 타이머 보간(0 아래로 안 감, 페이즈 불변),
  flip/foul/phase diff, 오래된 revision 무시
- **서버 GameStateTest (27) / RoomTest (13)** — TS 테스트 포팅 + 입장/만석/동시 탭/끊김/재접속/부전승/하트비트

```bash
npm run build     # tsc --noEmit(strict) + 프로덕션 번들
npm run preview   # 빌드 결과를 실제 배포와 같은 조건으로 확인
```

## 5. 알려진 한계

- **CSS 의 `mm` 는 명목 단위**(96dpi 기준)다. 브라우저가 보고하는 DPI 가 실제와
  다르면 물리 크기도 약간 어긋난다. 실기기에서 자로 재보고 `CARD_PHYSICAL_SIZE_MM` 을
  보정하면 된다.
- **라운드 간 180도 회전의 실효는 제한적이다.** 매 라운드 보드가 중립으로
  초기화되는 균일한 5x5 이므로, 회전으로 상쇄되는 것은 HUD 높이 차이 등으로 생기는
  보드의 화면상 위치 편차뿐이다.
- **무승부 라운드**는 명세에 규정이 없어 "승수를 주지 않고 같은 라운드 재경기"로
  구현했다. 25장이 홀수라도 아무도 안 먹은 중립 카드가 남으면 동점이 가능하다.
- **탭이 백그라운드로 가면 `requestAnimationFrame` 이 멈춘다.** 한 기기에서 둘이
  하는 v1 에서는 양쪽이 같이 멈추므로 공정성 문제는 없다.
