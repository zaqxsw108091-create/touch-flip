# 게임 명세

## 1. 개요

5x5 = 25장의 카드를 두 플레이어가 동시에 터치해 자기 색으로 뒤집는다.
라운드 종료 시 소유 카드가 많은 쪽이 승리. 25는 홀수이므로 무승부가 나지 않는다.

## 2. 라운드 구조

- 1라운드 = 시작 화면에서 선택: **30초 / 1분 / 2분** (기본 30초)
- **3판 2선승**
- 라운드마다 보드를 180도 회전시켜 자리 이점(가까운 카드가 유리한 현상)을 상쇄한다
- 시작 전 양쪽이 각자의 준비 버튼을 **누르고 있는 상태**에서 3-2-1 카운트다운
- 카운트다운 중 보드를 터치하면 파울: 해당 플레이어 500ms 입력 정지 + 화면 표시

## 3. 카드 소유권 판정

### v1 — 한 기기 로컬 대전

브라우저는 어느 손가락이 누구 것인지 알려주지 않는다. 따라서 **터치 지점 자체가
소유자를 인코딩**하도록 카드를 분할한다.

```
┌─────────────────┐
│   P2 터치 존     │  카드 상단 42%  → 플레이어 2 소유로 전환
├─────────────────┤
│   중립 띠        │  카드 중앙 16%  → 입력 무시 (오터치 방지)
├─────────────────┤
│   P1 터치 존     │  카드 하단 42%  → 플레이어 1 소유로 전환
└─────────────────┘
```

- 두 플레이어는 기기를 사이에 두고 마주 앉는다 (P1 아래, P2 위)
- 이미 상대 색인 카드도 자기 존을 누르면 뺏을 수 있다
- 색상 외에 패턴(P1 사선 / P2 점)으로도 소유자를 구분한다 (색약 대응)

### v2 — 태블릿 2대 온라인 대전

기기가 분리되므로 카드 분할이 불필요하다. 각자 자기 화면에서 카드 아무 곳이나
누르면 되고, 소유자는 WebSocket 세션이 결정한다. 각자 동일한 보드를 정면에서
보므로 자리 이점도 소멸한다.

## 4. 입력 공정성 상수

전부 `src/config.ts`의 단일 객체로 관리한다.

| 상수 | 값 | 목적 |
|---|---|---|
| `MAX_POINTERS_PER_PLAYER` | 2 | 손가락 5개로 5배 속도를 내는 것 방지 |
| `PLAYER_COOLDOWN_MS` | 50 | 플레이어별 전역 최소 입력 간격 |
| `CARD_LOCKOUT_MS` | 200 | 뒤집힌 직후 해당 카드 입력 무시 |
| `MAX_TOUCH_SIZE_PX` | 40 | 초과 시 손바닥으로 간주하고 무시 |
| `NEUTRAL_BAND_RATIO` | 0.16 | 카드 중앙 무효 영역 비율 (v1 전용) |
| `ROUND_DURATION_OPTIONS_MS` | 30000 / 60000 / 120000 | 시작 화면의 라운드 길이 선택지 |
| `ROUND_DURATION_MS` | 30000 | 기본 라운드 길이 |
| `POINTER_STALE_MS` | 2000 | pointerup 유실 시 포인터 자동 만료 |
| `FALSE_START_PENALTY_MS` | 500 | 부정 출발 시 입력 정지 시간 |
| `device.tablet.CARD_PHYSICAL_SIZE_MM` | 16 | 태블릿 모드 카드 한 변 |
| `device.phone.CARD_PHYSICAL_SIZE_MM` | 13 | 폰 모드 카드 한 변 |

### 입력 유효성 규칙

- `pointerdown`만 유효 판정. `pointermove`로 카드를 쓸어 넘기는 것은 무효
- `pointerType === 'touch'`만 허용. 마우스와 펜은 무시
- CSS `touch-action: none`, 더블탭 확대 / 스크롤 / 컨텍스트 메뉴 전부 차단
- 판정 시각은 `event.timeStamp` 사용 (주사율 이점 제거)

## 5. 레이아웃

- 카드 한 변을 화면 비례가 아니라 **물리 크기 약 16mm로 고정**한다.
  화면이 커질수록 보드가 커지면 손 이동 거리가 늘어 오히려 불리해진다.
- 보드는 화면 정중앙. 위아래에 각 플레이어의 점수/타이머 HUD
- 검증 해상도: 1366x768, 1920x1080, iPad 세로/가로
- 키보드만으로 준비 / 시작 / 재시작이 가능해야 한다

## 5.5 시작 설정 · 폰 모드 · NPC (v1.5)

게임 전 시작 화면에서 세 가지를 고른다. 마지막 선택은 `localStorage` 에 기억된다.

단계식 마법사: **기기 → 상대 → (NPC 단계 | 온라인 방) → 라운드 시간 → 시작**.

| 단계 | 선택지 |
|---|---|
| 기기 | 태블릿(카드 16mm) / 폰(카드 13mm, HUD 압축) |
| 상대 | 2인 로컬(기본) / 온라인 멀티(기기 2대) / NPC 1~5단계 |
| 라운드 시간 | 30초 / 1분 / 2분 (온라인은 방을 만든 쪽이 정한다) |

### NPC

상대가 없을 때 상대 역할을 한다. `config.npc.tiers` 에 단계별 실력이 정의된다.

| 단계 | 초당 탭 | 정확도 | 뺏기 성향 |
|---|---|---|---|
| 1 입문 | 1.5 | 55% | 0.2 |
| 2 보통 | 2.5 | 70% | 0.4 |
| 3 숙련 | 4.0 | 82% | 0.6 |
| 4 고수 | 6.0 | 92% | 0.75 |
| 5 괴물 | 9.0 | 98% | 0.9 |

NPC 공정성 규칙:

- NPC 탭도 `InputGovernor.submitTap` 을 거쳐 **쿨다운·카드 락아웃을 사람과 똑같이** 적용받는다.
  포인터 종류·접촉 크기·동시 포인터 수는 물리 필터라 적용하지 않는다.
- NPC 탭의 판정 시각은 프레임 시각이 아니라 **예약된 탭 시각**이다. rAF 가 늦어도 밀리지 않는다.
- NPC 는 부정 출발을 하지 않고, 사람이 준비를 누르면 0.3~0.8초 후 자동 준비한다.
- 탭이 백그라운드로 갔다 돌아오면 밀린 탭을 버린다 (`MAX_BACKLOG_MS`).
- NPC 모드에서는 카드를 분할하지 않는다 (`NPC_ZONE_MODE: 'full'`). 카드 전체가 사람 영역이고
  위쪽 HUD 도 뒤집지 않는다.

## 6. 아키텍처

```
src/
  config.ts          모든 튜닝 상수
  core/
    GameState.ts     보드 상태, 점수, 라운드 진행 (DOM 의존 없음)
    NpcPlayer.ts     NPC 의사결정 (DOM 의존 없음, 난수 주입)
    types.ts
  input/
    InputGovernor.ts pointer 이벤트 수신, 공정성 필터, 유효 탭만 방출
  render/
    Renderer.ts      GameState를 DOM에 반영
    BoardGeometry.ts 좌표 → 카드/존 (사각형 캐시, 위치 드리프트 자동 재측정)
    SetupScreen.ts   시작 설정 화면
  net/               v2 이후
    Connection.ts
    ClockSync.ts
tests/
  GameState.test.ts
  InputGovernor.test.ts
  NpcPlayer.test.ts
```

`InputGovernor`는 pointer 이벤트를 받아 위 규칙을 모두 통과한 것만
`{ playerId, cardIndex, timestamp }` 형태로 방출한다. `GameState`는 이 이벤트만
소비한다. 이 경계가 무너지면 공정성 보장이 무의미해진다.

## 7. 네트워크 (v2)

### 메시지 프로토콜 (JSON)

엔드포인트 `ws://<서버>:8080/ws`. 순수 WebSocket, 텍스트 JSON 한 줄 = 메시지 하나.

클라이언트 → 서버

| type | payload | 설명 |
|---|---|---|
| `join` | `{ roomCode?, token?, roundDurationMs? }` | 코드 없으면 새 방 생성. `token` 이 있으면 재접속 |
| `ready` | `{ held }` | 준비 버튼 홀드 상태 |
| `tap` | `{ cardIndex, tapTime }` | `tapTime` 은 v3 용 (v2 서버는 읽지 않는다) |
| `ping` | `{ clientTime }` | 시계 동기화용 (v3) |

서버 → 클라이언트

| type | payload | 설명 |
|---|---|---|
| `joined` | `{ playerId, roomCode, token, opponentPresent, roundDurationMs }` | `token` 은 재접속용 |
| `opponentJoined` / `opponentBack` | `{}` | 상대 입장 / 복귀 |
| `opponentLeft` | `{ graceMs }` | 상대 끊김, 유예 시작 |
| `state` | `{ serverTime, snapshot }` | 권위 상태. `snapshot` 은 클라 Snapshot 과 같은 모양, 2인 값은 `[P1, P2]` 배열 |
| `tapAck` | `{ cardIndex, accepted, reason }` | 내 탭의 판정 결과 (디버그용) |
| `pong` | `{ clientTime, serverTime }` | |
| `error` | `{ code, message }` | `room-not-found` / `room-full` / `not-joined` / … |

- 서버가 보드 상태의 **유일한 권위**를 가진다. 클라이언트에는 온라인 모드에서 `GameState` 가 없다.
- 방 코드 6자리로 페어링. 2명이 차면 양쪽 게임 화면으로 넘어가고, 카운트다운은 로컬과 똑같이 **양쪽이 준비를 누르고 있어야** 시작한다.
- **v2 판정 시각 = 서버 도착 시각**(`System.nanoTime` 기반 단조 시계). 핑이 낮은 쪽이 유리한 것을 알면서 감수하며, v3 에서 교체한다.
- 서버도 쿨다운·카드 락아웃을 다시 건다 (`ServerInputGovernor`). 클라이언트 필터는 물리 입력만 담당한다.
- 라운드 종료는 서버 틱(50ms)이 선언한다. 클라이언트는 `remainingMs` 를 수신 시각 기준으로 보간해 보여줄 뿐 페이즈를 바꾸지 않는다.
- 연결 끊김 시 5초 재접속 유예(같은 `token` 으로 `join`), 실패 시 상대 부전승. 상대가 없는 방에서 혼자 끊기면 방이 닫힌다.
- 라운드 시작 시 서버 `ServerInputGovernor` 도 쿨다운·락아웃을 초기화한다.

## 8. 지연 보상 (v3)

네트워크가 붙는 순간 핑이 낮은 쪽이 유리해진다. 이는 원래 없애려던
"기기 차이"보다 훨씬 큰 불공정이므로 반드시 처리해야 한다.

1. **시계 동기화** — 접속 시 ping-pong 20회. RTT가 가장 작았던 샘플로
   오프셋을 계산한다 (Cristian 알고리즘). 클라이언트는 탭 시
   `로컬시각 + 오프셋`을 `tapTime`으로 실어 보낸다.
2. **판정 윈도우 120ms** — 서버는 탭을 받자마자 처리하지 않고 버퍼에 담았다가
   `tapTime` 오름차순으로 정렬해 처리한다. 도착 순서가 아니라 실제 탭 순서로
   승부가 결정되게 하는 핵심 장치다.
3. **클라이언트 예측 + 롤백** — 자기 화면에서는 누른 즉시 뒤집어 보여주고,
   서버 확정 결과가 다르면 되돌린다. `CARD_LOCKOUT_MS = 200`이 롤백
   깜빡임을 시각적으로 흡수한다.
4. **타임스탬프 조작 방어** — 클라이언트가 보낸 `tapTime`이
   `(도착시각 - 오프셋)` 기준 ±150ms를 벗어나면 거부한다.
5. **매치 시작 게이트** — 양측 RTT 편차가 80ms를 넘거나 지터가 심하면
   "네트워크 상태가 불공정합니다"를 표시하고 시작을 막는다.

같은 Wi-Fi 또는 한 대의 핫스팟 사용을 UI에서 권장한다. RTT 5~15ms 환경에서는
위 문제가 사실상 소멸한다.
